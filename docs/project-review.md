# Current project state

The Quadruplicate is a Bun/TypeScript municipal-code and civic-intelligence
platform with a bounded static public edition. Its release contract covers
source custody, explicit gaps, finite acquisition, runtime API validation,
private diagnostics, staged indexes and recoverable publication. The
[release acceptance receipt](release-acceptance.json) records measured checks
and snapshot identity. [TODO.md](../TODO.md) is the only open item-level
backlog; [CHANGELOG.md](../CHANGELOG.md) is the only version history.

## Evidence and acquisition

The refreshed municipal edition contains **245 articles and 2,206 sections**.
Retained source bytes, extraction receipts, separately fetched section
fragments and exported section text have distinct hashes. Verification
separates local custody, current table of contents and a deterministic live
sample. A live mismatch, missing sample or incomplete edition cannot produce
publication eligibility. This is bounded source/extraction evidence, not a
claim of universal legal completeness or continuing remote currency.

The canonical source registry inventories the actual enabled producers and
reference/discovery boundaries. HTTP reachability is separate from parser
success and observation validity. Source health carries stable identity,
checked time and explicit `ok`, `empty`, `unavailable` or `stale` states.
Source counts, registry fingerprint and observed gaps are recorded in the
acceptance receipt and published snapshot rather than duplicated here.

Public source refresh includes news, official meeting archives, YouTube
transcripts, citation-only Triplicate references, event discovery and all
twenty hazard monitors. Catalog access does not establish issued permit or
landing records. Statewide fuel is not local pricing. Unestablished local AIS
coverage stays unavailable. HMS density is qualitative: measured PM2.5, AQI
and numerical forecasts remain unknown unless a real product provides them.

The optional meeting-document producer retains exact PDF bytes and native
page-addressable text with hashes, offsets and extraction uncertainty. It
does not infer votes, ordinance dates or legal meaning from page extraction.
County portal discovery remains a source gap when the observed response does
not establish usable records.

Acquisition uses shared DNS/IP and redirect policy, finite total budgets,
streaming wire/decoded caps and robots evaluation by request path. Owned
subprocess groups are killed and reaped on timeout, cancellation, overflow
and detached-descendant cases. Remaining browser-specific cancellation and
source-validity acceptance is scoped in TODO.

## Runtime and private state

Structural OpenAPI is the API method, authentication and input authority.
Runtime guards reject malformed or excessive query/body/history inputs;
unsupported methods return their declared method contract. Authentication and
quota identity use the socket peer and explicit trusted-proxy policy. Public
metadata omits credentials, raw provider URLs and private paths.

Search applies field/filter contracts consistently. Superseded browser
requests cannot overwrite the latest query or reopen a cleared dropdown.
Local rendering assets and resource-free sanitization keep generated text
inert. Core native journeys exercise keyboard interaction, missing data,
denied storage, delayed responses, safe rendering and chat terminal states.
The remaining all-surface accessibility and module work is explicit.

Query content, history and generated answers are not retained by default.
Optional private receipts retain allowlisted operational metadata with byte,
row and age bounds. Public Pages projection is an explicit per-family DTO;
the complete publication tree is scanned for private paths, credential URL
aliases, unsafe protocols and unknown copied artifacts.

Durable stores serialize read/merge/write operations with ownership leases.
Curation has one parent budget, durable incomplete/complete attempt receipts
and separate batch/store leases. Retry recovery reuses a retained successful
summary only when source, text fingerprint, citation/provenance, model and
prompt lineage match exactly. Source-only, corrupt or ambiguous evidence
cannot suppress a retry. Sequential multi-file writes are not advertised as
cross-directory transactions.

## Indexing and generated evidence

Code indexes activate a staged complete collection and a manifest bound to
corpus bytes, configuration and actual owned vector IDs. Missing vectors,
changed geometry and partial rebuilds cannot advertise readiness. Transcript
ownership and reindex requirements are separate from code ownership.
Normal and streaming chat share ordered retrieval/context construction;
streaming has one terminal outcome and incomplete answers do not enter
successful history.

Generated answers remain **unverified**. Citation validation establishes
identity against retrieved records; it does not establish semantic support,
independent corroboration, legal currency or factuality. The versioned RAG
benchmark records listed-section retrieval, citation behavior, abstentions,
failures and exact corpus/configuration identity. Its small native evaluation
is a measured baseline; broader support/usefulness evaluation remains open.

## Publication and verification

Publication chooses one complete verified municipal bundle or the whole
reviewed seed. Failed/partial current acquisition cannot mix individual seed
and live files. Immutable input and output-tree receipts, staged activation,
previous-state retention and restart recovery support review and rollback.
Legitimate empty feeds remain empty and valid.

The authoritative gate runs structural contracts, strict application types,
independent strict test types, manuscript source checks, geo-contract rebuild,
the fenced offline suite and actual line coverage. Both plain and covered
runs check the fence in `finally`, including failure and timeout. Test
fixtures use isolated artifact roots; real local HTTP/process/browser cases
exercise failure boundaries without ambient provider access.

Native acceptance separately exercises the populated GUI, local model/vector
services, pinned Linux application image, exact exported Pages in four
viewport sizes, PDF/HTML rendering and the external geo consumer. The
acceptance receipt distinguishes those results from hosted workflows and
live deployment. Research rendering names the external template revision;
claim-ledger boundaries continue to exclude legal, factual and safety efficacy.
